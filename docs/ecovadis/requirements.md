# EcoVadis Workflow Requirements (Paraphrased)

## Evidence relevance and linkage
- Supporting documents must be relevant to the selected questionnaire answer and sustainability topic.
- Evidence should be linked directly to the answer option it supports, not uploaded as unstructured archives.
- Evidence attachments should include page references and can include explanatory comments for reviewer traceability.

## Scope relevance
- Documents must be in scope for the assessed perimeter (Group, Entity, or Site).
- Scope metadata should indicate whether a document supports tenant-level, company-level, or site-level coverage.

## Document cap
- A maximum of 55 new documents is allowed for each assessment.
- The cap applies per assessment; prior-assessment documents do not consume the current assessment's 55-document quota.

## Metadata and validity checks
- Documents should include core metadata (issue date, type, scope coverage, language, encryption status).
- KPI/reporting evidence should be recent (2-year window by default).
- Policy/action evidence can use a longer validity window (configurable).
- Missing issue date is treated as a warning, not a hard block.

## File quality constraints
- Accepted files should be standard business formats (for example PDF/Office/image) with readable, reviewable content.
- Combined "evidence bundles" made only to bypass limits are not acceptable.
- Encrypted files are invalid for assessment submission.
